# HybridRAG 学习指南与面试准备

目标是讲清楚一条“文档变成答案”的路径，再理解每个模块的责任。先总览，不逐行读。

## 一句话介绍

HybridRAG 是本地知识问答项目：上传 TXT 后切分文本、调用百炼 Embedding 写入 Chroma；提问时向量检索和 BM25 关键词检索分别召回，再用 RRF 融合排序，将相关片段交给 Qwen 生成答案。

## 先画出两条线

```text
上传：TXT → UTF-8 解码 → MD5 内容去重 → 文本切分 → Embedding → Chroma
提问：问题 → 向量检索 ─┐
                  ├→ RRF 排序 → Top-K 片段 → Prompt + 对话历史 → Qwen → 回答
            BM25 ──┘
```

这里有两路**检索**和一个**融合步骤**。RRF 本身不是第三种检索器。用户问题、模型回答保存在当前会话的本地历史文件；上传文件名列表单独保存在 JSON。

## 五步熟悉项目

### 第 1 步：走页面，不读代码

上传 `assets/` 中一份 TXT，问一个资料里有明确答案的问题，再问一个资料没有覆盖的问题。观察系统何时能回答、何时应说“没有查到”。记住：页面目前不显示独立引用列表。

### 第 2 步：追上传链路

读 `app.py` 的上传部分，再看 `knowledge_base.py` 的 `upload_by_str`。只回答：文件怎样解码？MD5 比较什么？什么时候切分？切分后存在哪里？为什么 `source` 元数据有用？不需要先研究 Streamlit 的所有 API。

### 第 3 步：追提问链路

读 `app.py` 的 `st.chat_input`，再读 `rag.py` 的 `__get_chain`。用箭头标出 `问题 → retriever → 格式化参考资料 → Prompt → Qwen → 输出`。`RunnableWithMessageHistory` 用会话 ID 找历史文件，读 `file_history_store.py` 即可。

### 第 4 步：专门理解混合检索

读 `vector_stores.py` 和 `hybrid_retriever.py` 的 `invoke`。向量检索按语义相似度找片段；BM25 根据词频、逆文档频率和文档长度打分。中文当前按单字切，英文按词切。两路结果由 RRF 按排名累加 `1 / (60 + 排名)`，同一内容及来源合并，最后取 `final_top_k`。

### 第 5 步：自己做一次对比

准备一份包含明确编号或专有名词的 TXT，再准备一条同义改写问题。分别用混合检索和纯向量模式观察返回答案。修改 `config_data.py` 的 `use_hybrid` 后重启应用；记录现象与可能原因。一次人工观察不能证明总体准确率提升，要有标准问题集和指标才能下结论。

## 面试常见追问：用自己的话回答

1. **什么是 RAG？** 先从外部知识库检索相关片段，再把片段放进提示词，要求模型据此回答。它把知识更新与模型训练分开。
2. **为什么混合检索？** 向量检索覆盖语义改写，BM25 对关键词、编号等字面信息更敏感；融合可综合两边的排名，但效果需评估。
3. **BM25 在项目里怎么实现？** 从 Chroma 读取文本，在内存建立词频和文档频率；每次查询检查知识库是否变化，再按 BM25 公式排序。中文分词只是单字级简化方案。
4. **RRF 为什么不直接相加分数？** 向量相似度与 BM25 分数尺度不同；RRF 只用名次，按 `1/(60+rank)` 累加，免去直接校准分数。也有信息损失和参数选择问题。
5. **如何避免重复上传？** 对完整文档内容算 MD5，已记录则拒绝再入库；它处理相同内容重复上传，不解决相似内容去重，也不是安全校验。
6. **新上传文档会不会被 BM25 看见？** `HybridRetriever.invoke` 在查询时检查 Chroma 文档和元数据是否变化，变化时重建内存关键词索引。
7. **没有检索结果怎么办？** Prompt 要求只依据参考资料，不足时明确说没有查到；模型仍可能犯错，当前没有答案质量自动评估。
8. **对话历史在哪里？** 按浏览会话 ID 写入 `chat_history/` 文件。向量知识库在 `chroma_db/`；它们是两类不同的数据。
9. **现在的限制是什么？** 仅 TXT、简易中文分词、每次查全量文档以检测变化、没有来源展示和量化评测，适合小规模本地演示。

## 面试前的自检

不看代码，能在 60 秒内画出上传和提问两条线；能解释“两个召回列表如何合成一个列表”；能说出一个最可能失败的查询场景和下一步如何评估。答不上来就回到对应模块和页面现象，不需要背完整框架源码。
